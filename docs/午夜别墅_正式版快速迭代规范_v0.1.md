# 《午夜别墅》正式版快速迭代规范

| 项目 | 内容 |
|---|---|
| 文档版本 | V0.1 |
| 文档状态 | 讨论草案 |
| 当前阶段 | 正式版快速迭代期 |
| 适用范围 | 游戏功能、内容、表现、存档与发布质量 |
| 依据 | `AGENTS.md`、PRD V1.3、README、现有测试与实现 |

> 本文档定义项目离开 MVP 阶段后的迭代方式与交付底线。正式版不等于内容冻结，快速迭代也不等于扩大产品范围；两者都以持续交付可玩、可验证、可回滚的玩家体验为目标。

---

## 1. 阶段定义

“正式版快速迭代期”表示：

1. 项目主线从“证明 MVP 可行”转为“持续完善可玩版本”。
2. 重点从补齐基础闭环，转为修复实际体验问题、替换临时资产、提升完成度与稳定性。
3. 未完成项仍可存在，但必须明确记录为当前版本缺口，不能再用 MVP 口径弱化交付要求。
4. 既有产品边界继续有效：第一人称探索、NPC 预设对话、线索与谜题、多结局、本地存档、桌面浏览器和静态 Web 部署。

正式版不自动包含账号、云存档、常驻后端、在线社交、战斗或实时 AI 对话。改变这些边界需要单独立项并获得明确确认。

## 2. 迭代目标与优先级

每轮迭代应围绕一个玩家可感知或工程质量上可验证的目标，按以下顺序处理：

1. **阻断问题：** 崩溃、数据丢失、无法继续游玩、明显存档损坏或核心流程阻塞。
2. **体验完成度：** 交互反馈、镜头与移动、UI 可读性、叙事连续性、性能和兼容性。
3. **内容与资产：** 正式模型、贴图、音频、动画、剧情演出和内容缺口。
4. **技术健康：** 可维护性、测试覆盖、资源释放、工具链和文档一致性。

低优先级润色不得挤占阻断问题修复；新增内容不得绕开已有存档、对话图和剧情条件校验。

## 3. 迭代单元与交付方式

一个迭代单元应具有：

- 明确的玩家问题或工程问题。
- 最小但完整的实现范围。
- 可复现的验收方式。
- 对存档、剧情状态、资源加载和 UI 输入锁定的副作用说明。
- 必要时可独立回退的变更边界。

迭代类型可区分为：

| 类型 | 典型内容 | 交付要求 |
|---|---|---|
| 修复迭代 | 崩溃、卡流程、存档异常、输入冲突 | 复现步骤、回归测试、优先发布 |
| 体验迭代 | UI、交互、镜头、性能、可读性 | 前后对比、目标浏览器验证 |
| 内容迭代 | 场景、资产、音频、演出、剧情补完 | 内容依据、授权记录、流程回归 |
| 工程迭代 | 测试、工具链、资源生命周期、文档 | 风险说明、自动化验证 |

具体发布节奏、版本号规则和灰度/回滚方式仍需确认，不在本文档中预设。

## 4. 完成定义

一项改动只有同时满足适用条件，才可标记为完成：

1. 行为与边界符合已确认需求，没有擅自增加产品范围。
2. TypeScript 类型检查、ESLint、测试和生产构建通过；不适用的检查需说明原因。
3. 涉及界面、3D 交互或输入锁定时，在目标桌面浏览器完成手动冒烟验证。
4. 涉及存档结构时，提供版本迁移、损坏数据处理和旧存档回归验证。
5. 涉及对话、线索、谜题或结局时，遵守对应数据校验和静态检查要求。
6. 涉及资源时，确认命名、来源、授权、运行时加载和释放。
7. 公共接口、存档结构、内容格式或架构变化同步更新文档和测试。
8. 交付说明列出实际执行的验证、未验证项和真实风险。

## 5. 不可突破的迭代边界

- 未经确认，不更换 PlayCanvas、React、Vite、TypeScript 或本地 IndexedDB 的技术方向。
- 未经确认，不引入常驻后端、账号、云存档、外部 AI 服务、埋点或追踪 SDK。
- 不得为了快速迭代伪造剧情设定、降低类型安全、跳过存档迁移或忽略资源授权。
- 不得以“正式版”为由一次性重写核心架构；优先小步替换、保持可运行和可回滚。
- 不得删除现有功能、用户数据或资产来简化问题，除非用户明确批准。
- 不得把尚未执行的测试或浏览器验证描述为已通过。

## 6. 文档职责

| 文档 | 当前职责 |
|---|---|
| `AGENTS.md` | 工程约束、技术基线、数据与范围红线 |
| PRD | 产品定位、当前版本范围与验收基线 |
| 本文档 | 正式版迭代方式、完成定义与发布前待决事项 |
| GDD | 玩法、体验与关卡设计原则 |
| 世界观、故事线、结局文档 | 已确认叙事事实与内容依据 |
| 技术架构文档 | 系统边界、模块职责与技术约束 |
| 资产清单与资产 README | 资产规格、优先级、授权与验收状态 |
| README | 仓库实际能力、运行方式与当前缺口 |

历史版本文档可以保留旧阶段表述，但必须标明“历史记录”或由新版本取代；当前工作文档不得继续把 MVP 当作当前阶段。

## 7. 当前版本优先补齐项

以下项目来自现有 README 和仓库状态，不代表新增功能：

1. 用正式场景与 GLB 资产替换灰盒。
2. 完成音频系统、音量设置与相关持久化。
3. 补齐第三方素材授权与署名清单。
4. 继续验证存档兼容、资源释放、目标浏览器和实际帧率。
5. 同步维护剧情、资产、测试与当前版本说明，减少文档与实现漂移。

## 8. 待讨论并确认

1. “正式版”的当前发布状态与对外版本号。
2. 迭代节奏、发布渠道、热修复权限与回滚方式。
3. 需要保证兼容的旧存档版本范围与最短兼容周期。
4. 目标浏览器、最低硬件和性能验收预算。
5. 是否允许任何形式的匿名运行数据采集；默认必须保持不采集。
6. 下一阶段是否扩展章节、区域、NPC 或语言支持，以及相应内容边界。
7. 正式发布前采用“自动化检查 + 手动冒烟 + 验收清单”的统一门禁。
