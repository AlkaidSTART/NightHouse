# 《午夜别墅》游戏设计文档（GDD）

**版本：** V1.0\
**依据：**《午夜别墅》PRD V1.2\
**产品形态：** 单人第一人称写实悬疑探索游戏\
**目标平台：** 桌面端 Web 浏览器\
**状态：** 设计基线，剧情细节待进一步确认

------------------------------------------------------------------------

## 1. 设计目标

《午夜别墅》希望让玩家通过第一人称探索、人物互动和线索推理，逐步拼出一段被隐藏的真相。游戏的主要乐趣来自：

1.  **空间探索：** 在一座具有生活痕迹和叙事信息的别墅中寻找异常。
2.  **人物判断：** 通过 NPC 的言行、态度和信息差判断其可信度。
3.  **线索关联：** 将文件、物品、环境细节与对话信息联系起来。
4.  **选择后果：** 玩家选择影响后续信息、人物状态和最终结局。
5.  **氛围沉浸：** 使用灯光、声音、空间节奏和镜头控制营造悬疑感。

本文件描述玩法与内容设计，不替代 PRD 中的产品范围和技术约束。

## 2. 核心体验支柱

### 2.1 探索先于解释

不要在开场一次性解释别墅的全部背景。先让玩家观察到不协调的物品、异常的声音和被刻意隐藏的信息，再通过线索与
NPC 对话逐步补足背景。

### 2.2 NPC 是叙事角色

NPC 不应只是任务发布器。每名 NPC 都应有： - 明确的身份与目标； -
对事件的个人理解； - 知道与不知道的信息边界； - 对玩家行为的反应； -
至少一个可被玩家察觉的性格特征。

### 2.3 线索必须产生作用

每条重要线索至少服务于一项用途： - 解锁新对话； - 解锁新区域； -
提供谜题答案的一部分； - 改变 NPC 态度； - 改变结局判定条件。

避免只为填充场景而放置没有后续用途的关键线索。

### 2.4 恐怖感以悬疑为主

美术与声音以压迫、未知和不安为主，不依赖持续高强度惊吓。惊吓事件应有铺垫，并服务于剧情。

## 3. 玩家体验流程

``` text
主菜单
  ↓
新游戏
  ↓
开场叙事 / 操作引导
  ↓
进入别墅
  ↓
自由探索当前开放区域
  ↓
发现物品、环境异常或 NPC
  ↓
查看线索 / 进行对话
  ↓
更新任务与剧情状态
  ↓
解锁区域或谜题
  ↓
关键选择
  ↓
结局演出
  ↓
结局回顾 / 返回主菜单
```

### 3.1 节奏建议

  阶段       玩家感受         设计目的
  ---------- ---------------- ----------------------------
  开场       好奇、陌生       建立进入别墅的理由
  初次探索   不安、观察       教会基本操作并展示环境异常
  初次对话   怀疑、试探       介绍 NPC 和信息差
  线索收集   推理、关联       让玩家形成自己的解释
  谜题推进   紧张、专注       将信息转化为行动
  真相揭示   意外、重新理解   回收前期伏笔
  结局       释然或不安       呈现选择带来的结果

## 4. 关卡结构

### 4.1 场景区域建议

  区域           主要功能         设计内容
  -------------- ---------------- ------------------------------
  入口 / 门厅    引导与建立氛围   开场信息、基础交互提示
  客厅           初步探索         家具、照片、公共区域线索
  走廊           空间连接         视线引导、声音线索、门的状态
  书房           信息密集区       日记、文件、书籍、谜题线索
  卧室           人物叙事         私人物品、关系线索
  储物区域       道具与环境线索   旧物、箱柜、可组合信息
  核心剧情区域   真相揭示         关键事件、最终选择或结局触发

上述是建议结构，实际布局需结合最终故事与资产制作能力裁剪。

### 4.2 区域解锁原则

-   初始开放区域应足以让玩家理解移动、观察和交互。
-   新区域应由明确线索、道具或剧情事件解锁。
-   不要让玩家因遗漏非关键装饰物而永久卡关。
-   关键路径应提供不止一种信息提示，但不必提供直接答案。
-   重要门锁和谜题应有清晰的反馈。

## 5. NPC 设计规范

### 5.1 NPC 角色卡模板

每名 NPC 使用统一角色卡：

  字段         内容
  ------------ ----------------------------
  NPC ID       稳定唯一标识
  姓名         角色姓名
  身份         在别墅中的身份
  外在表现     外貌、动作、说话方式
  性格关键词   2--4 个关键词
  公开目标     角色愿意表达的目标
  隐藏动机     角色不主动透露的动机
  已知信息     角色确实知道的事实
  错误认知     角色误解或相信的内容
  对玩家态度   初始态度及变化条件
  关联线索     与角色有关的线索 ID
  对话节点     对话树入口
  剧情作用     解锁、误导、解释或推动事件

### 5.2 NPC 状态

建议将状态拆成三类： - **关系状态：** 玩家与 NPC
的信任、戒备或亲近程度。 - **剧情标记：**
玩家是否问过某个问题、是否展示过某条线索。 - **当前表现：** NPC
当前情绪、动作和可用对话。

不要让一个简单的关系数值决定全部行为。关键反应应由明确剧情标记控制，关系数值只用于补充细节。

### 5.3 对话设计规则

-   每段对话应有明确目的。
-   玩家选项应表达不同态度或调查方向，而不是换一种说法问同一件事。
-   重要选项应说明其实际含义，避免误导玩家。
-   NPC 不应知道玩家尚未发现的信息，除非剧情明确允许。
-   关键线索可以被 NPC 解释，但不能由 NPC 无条件代替玩家完成推理。
-   对话结束后应有清晰返回探索的操作。

### 5.4 对话数据结构示例

``` json
{
  "id": "npc_housekeeper_intro_01",
  "npcId": "housekeeper",
  "conditions": ["story.entered_hall"],
  "lines": [
    { "speaker": "npc", "text": "你终于到了。" }
  ],
  "choices": [
    {
      "id": "ask_owner",
      "text": "询问别墅主人",
      "next": "npc_housekeeper_owner_01",
      "effects": ["dialogue.asked_owner"]
    },
    {
      "id": "end",
      "text": "暂时离开",
      "next": null,
      "effects": []
    }
  ]
}
```

此结构仅为内容配置示例，最终字段以技术实现为准。

## 6. 线索与谜题设计

### 6.1 线索分级

-   **主线线索：** 推进核心剧情，必须容易被玩家发现或有替代提示。
-   **辅助线索：** 补充人物背景、解释事件细节。
-   **氛围线索：** 不影响通关，但丰富环境叙事。

### 6.2 线索卡模板

  字段       说明
  ---------- --------------------
  clueId     唯一 ID
  名称       玩家看到的标题
  内容       可阅读或观察的信息
  所属区域   线索所在位置
  发现条件   触发条件
  关联角色   相关 NPC
  关联谜题   相关谜题 ID
  剧情效果   更新的状态标记
  重要级别   主线 / 辅助 / 氛围

### 6.3 谜题设计原则

-   谜题答案必须能从已获得的信息中推导。
-   提示应分层：环境暗示、线索文本、可选的进一步提示。
-   错误操作要有反馈，不能让玩家无法判断是否操作成功。
-   关键谜题避免依赖像素级点击或不明显的隐藏热点。
-   谜题完成后要有声音、动画或状态变化反馈。

## 7. 剧情状态与分支

建议使用事件驱动状态机。

典型事件： - `scene.entered` - `npc.interacted` -
`dialogue.choice_selected` - `clue.discovered` - `puzzle.completed` -
`door.unlocked` - `story.flag_changed` - `ending.triggered`

剧情状态由统一模块维护。对话、任务、场景和结局系统通过事件或状态查询协作，避免各模块私自修改彼此的数据。

### 7.1 结局设计要求

MVP 至少包含两个可区分的结局。每个结局必须定义： - 触发条件； -
进入结局前的必要状态； - 结局演出； - 对前置线索和选择的回收； -
结局后的可操作选项。

具体故事内容和触发条件待剧本阶段确定。

## 8. 镜头、灯光与声音

### 8.1 镜头

-   第一人称视角为主。
-   视角移动应平滑，避免过度惯性。
-   镜头晃动保持克制。
-   关键剧情可短暂控制镜头，但应尽量避免长时间剥夺玩家控制权。
-   对话时可通过 UI、NPC 朝向和轻微镜头调整建立交流感。

### 8.2 灯光

-   使用局部光源引导玩家注意力。
-   重要线索应具备可辨识度，不能完全淹没在黑暗中。
-   优先烘焙静态光照，谨慎使用动态阴影。
-   避免全场景统一压暗导致玩家看不清交互对象。

### 8.3 声音

声音类别： - 环境底噪； - 房间空间音； - 脚步与移动音； - 物品交互音； -
NPC 对话； - 剧情提示音； - 关键事件音效。

声音应帮助玩家判断空间、距离和事件变化，不应持续使用高音量惊吓音效。

## 9. UI 体验规范

-   HUD 保持简洁，优先让玩家观察场景。
-   交互提示短而明确。
-   对话选项应易读、可区分。
-   线索查看界面应突出内容，不堆叠装饰。
-   任务提示只展示当前必要目标。
-   暂停菜单和设置入口保持一致。

## 10. 内容制作与验收

每个关卡交付时应包含： - 场景平面布局； - 玩家主要路线； - NPC
位置与活动范围； - 可交互物品清单； - 线索依赖关系； -
谜题说明与答案依据； - 剧情事件触发条件； - 音效与灯光备注； -
测试路线和预期结果。

每名 NPC 交付时应包含： - 角色卡； - 对话树； - 状态变化表； -
关联线索； - 动作需求； - 测试用例。

## 11. 待设计内容

以下内容不能在缺少故事设定时擅自定稿： 1. 主角身份与进入别墅的原因； 2.
别墅事件的真实经过； 3. NPC 的具体人数、姓名和关系； 4.
主要悬念及核心反转； 5. 关键线索链； 6. 谜题答案； 7.
各结局的具体叙事内容。

这些内容应在正式剧本大纲阶段统一确定，再据此冻结关卡与资产需求。
